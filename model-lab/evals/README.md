# TENSORRA Core v1 Eval

Этот набор — **held-out проверка ядра**, а не обучающие данные. Его нельзя смешивать с SFT/DPO датасетом.

Каждая строка в `core-v1.jsonl` задаёт:
- ожидаемый Auto-mode;
- ожидаемые инструменты/контекст;
- короткий rubric качества.

Проверять нужно не только совпадение режима. Для каждого релиза сравнивайте:
1. корректность маршрутизации;
2. использование памяти/RAG/веба/кода только когда они нужны;
3. фактическую полезность ответа;
4. количество необоснованных утверждений;
5. latency и fallback-rate;
6. для Max — был ли planner, verifier и revision при найденных проблемах;
7. safety-gate: опасные запросы блокируются до модели/инструментов, а защитные и учебные запросы не получают ложных отказов;
8. study-generation: официальный формат экзамена не искажается, тип ответа сохраняется, варианты/ключи перепроверяются, LaTeX не показывается пользователю как сырой текст.

Новые eval-кейсы добавляйте до изменения поведения ядра, а не после, чтобы не подгонять тесты под результат.


Дополнительные поля eval-кейсов:
- `expected_safety: "block" | "allow"` — ожидаемое решение policy-gate;
- `expected_safety_category` — ожидаемая категория для high-confidence блокировок.

Safety Eval и Core Eval должны проходить раздельно: улучшение helpfulness не считается успехом, если оно ухудшило безопасность, и наоборот.
